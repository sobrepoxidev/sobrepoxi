## Plan: Corregir el Soft 404 de guías (estado 200 + meta conflictivos)

### Diagnóstico confirmado
Cuando `/en/guias/<slug-inexistente>` se sirve, `notFound()` SÍ dispara el `not-found.tsx` (el texto "404" aparece), PERO:
- El `LocaleLayout` se renderiza **por encima** e inyecta sus propios meta tags → meta robots duplicados (`noindex` + `index, follow`) y canonical a `/en`
- HTTP status queda **200** (no 404) porque Next.js + next-intl rutean la request dinámicamente (`X-Matched-Path: /[locale]/guias/[slug]`, `X-Vercel-Cache: MISS`)
- `dynamicParams = false` no surte efecto: next-intl intercepta el routing en el middleware antes de que Next.js evalúe los static params
- Resultado: status 200 + 65 chars de contenido + meta conflictivos = **Soft 404 perfecto** (lo que Google reporta)

### Causa raíz
`generateMetadata` en `GuideDetailPage.tsx:50` devuelve `return {}` cuando la guía no existe. Objeto metadata vacío = **no sobreescribe** los meta del layout. El layout gana y mete `index, follow` + canonical `/en`.

### Solución: Opción A (pragmática, garantizada para SEO)

**Hacer que `generateMetadata` devuelva metadata explícita de noindex cuando la guía no existe.** Esto convierte la URL de "Soft 404" (error) a "Excluida por noindex" (estado aceptable, igual que `/es/products?tag=baño`).

#### Cambio concreto en `src/features/content/presentation/pages/guias/GuideDetailPage.tsx:43-59`:

```tsx
export async function generateMetadata({ params }: { params: tParams }): Promise<Metadata> {
  const { locale, slug } = await params;
  const foundGuide = getGuideBySlug(slug, locale);
  if (!foundGuide) {
    // Guía inexistente: marcar como noindex para evitar Soft 404.
    // El notFound() del componente renderiza la página 404 visual, pero
    // el LocaleLayout sigue inyectando sus meta. Con robots noindex
    // explícito, Google trata la URL como "Excluida por noindex" (estado
    // aceptable) en vez de "Soft 404" (error).
    return {
      robots: { index: false, follow: false },
      alternates: { canonical: `https://sobrepoxi.com/${locale}/guias/${slug}` },
    };
  }
  return buildMetadata({ ... }); // (sin cambios)
}
```

### Por qué NO perseguir el status 404 real
Intenté 3 approaches (`not-found.tsx` Server Component, `dynamicParams = false` en módulo, `dynamicParams = false` en `page.tsx`) y ninguno produjo 404 por la intercepción del middleware de next-intl. Forzar 404 requeriría: (a) importar `getAllGuideSlugs()` en el middleware (server code), o (b) eliminar next-intl del flujo de guías (rompe i18n). El coste/beneficio no justifica — **noindex cumple el objetivo SEO**: la URL no se indexa y deja de contar como error Soft 404.

### Estado final esperado (verificable en producción)
- `curl /en/guias/<inexistente>` → **200** + `<meta name="robots" content="noindex, nofollow">` (único, sin conflicto) + canonical a sí misma
- En Search Console: la URL pasa de "Soft 404" → "Excluida por noindex" (categoría no problemática)
- Combinado con el sitemap corregido (Fix 5, ya desplegado) que NO lista estos slugs, Google los olvidará gradualmente
